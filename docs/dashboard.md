## 一、核心：上面那排 tag 有兩種，不是同一件事

```
待處理  已詢問  已出價  湊單籃  已購買  觀察中  已過期  全部  │  💎高價卡  💠稀有卡  │  👤賣家
└────────────── 流程狀態（互斥，一張卡只在一格）──────────┘  └─ 分類（跨狀態）─┘  └ 換版面 ┘
```

| | 回答什麼 | 互斥？ |
|---|---|---|
| **流程狀態** | 這張卡我處理到哪一步了 | 是。一張卡同時只能在一格 |
| **分類** | 這張卡**是什麼** | 否。跨狀態存活 |

**為什麼分類不能當成流程狀態的第九、第十個值**：那會在你按下「已出價」的
瞬間把分類洗掉。高價卡出價之後**還是高價卡**——你之後回頭看「已購買」時，
必須分得出哪些是當初的高價卡。兩個維度正交，所以是兩個欄位
（`signals.state` 與 `signals.bucket`）。

⚠️ **「略過」沒有自己的分頁**。按過略過的卡只在「全部」裡看得到。
這是刻意的——略過就是不想再看到它。

## 二、一個晚上的動線

### 1. 開「待處理」

新掃到、還沒看過的標的。逐筆決定去處：

| 你的判斷 | 按 | 之後在哪 |
|---|---|---|
| 便宜到接近白嫖，想再等等 | 觀察中 | 觀察中 |
| 貴但值得盯（PSA9/10、1999 真紅眼、SM-51…） | 💎 高價卡 | 高價卡分頁（**同時**自動進觀察中） |
| 一刷／2002-2003 賽事卡，等降價 | 💠 稀有卡 | 稀有卡分頁（同上） |
| 想跟同賣家的其他貨合併運費 | 湊單籃 | 湊單籃 |
| 要問賣家寄送／能不能合併 | 已詢問 | 已詢問 |
| 不要 | 略過 | 只在「全部」 |

**指派分類時的狀態連動**：如果卡片還是「待處理」，指派分類會自動一併升成
「觀察中」（因為分類本來就代表你在盯它）。但**已購買、略過的不會被打回**——
分類只補狀態，不覆蓋你已經做過的決定。

再按一次已亮起的分類按鈕 = 取消分類。

### 2. 開「🙈 隱藏競標中」

競標的**現價會漲，不是你能付的價格**，對它唯一能做的動作是出價等結標。
先把它們收起來，專心處理一口價的標的。

### 3. 要打競標時，切「🔨 競標」分頁

預設按**可行動性**排序：

```
⚡ 有出價上限 ＋ 現價低於上限 ＋ 24 小時內結標   ← 最前面，現在就該看
   有空間但還早
   沒上限／已無空間                              ← 最後
```

同一梯隊內照結標時間由近到遠。再加「✅ 有空間的競標」就只剩現在真能出手的那批。

### 4. 想長期盯一個賣家，到「👤 賣家 → 🎯 監控名單」貼他的賣場 URL

輸入框在監控名單表格上方，樣式與鑑價／關鍵字搜尋一致：貼 URL、按「📌 釘選」。

支援 Yahoo 拍賣、Mercari 日本／台灣、eBay 的賣家頁 URL，也可以直接輸入
`site:seller_id`。**eBay 店鋪頁**（`ebay.com/str/…`）會即時抓頁面解出真實帳號
（約 1-2 秒）——店鋪名稱與 API 帳號是兩回事（實例：店鋪 `merrycorporation`
的帳號是 `merry_tcg`），解析不出來時會**拒絕並要你改貼 `/usr/` 頁**，不會亂猜。
Mercari **台灣**的賣家頁會自動換軌到 Buyee 的 Mercari 鏡像（台日同一個賣家 ID），
因為 tw 站本身擋機器人。

釘選與名單上其他賣家的差別：

| | 自動入選（Alpha 軌／供給軌） | 📌 釘選 |
|---|---|---|
| 名額 | 佔 30 組上限 | **不佔名額、無上限** |
| 掃描頻率 | 4 批輪替，每人約 240 分一次 | **每批都掃**，約 60 分一次 |
| 會不會被擠掉 | 會（分數更高的候選進來時） | **永不被自動淘汰** |

已在名單上的賣家再釘選 ＝ 升級成釘選（使用者明講要追蹤 > 演算法入選），
掃描紀錄保留；重複釘選同一人 ＝ 改備註。要停止追蹤按該列的「移出名單」。

> ⚠️ 移除按鈕對釘選列一樣有效，**按下去就真的移出**（軟刪除、可再釘回來）。
> 名單頂端的「📌 釘選 N 組」只算還在追蹤的。

## 三、控制項速查

| 位置 | 種類 | 作用 |
|---|---|---|
| 篩選：全部／只看觸發／只看未觸發／🔨競標 | **單選** | 換一批看 |
| 🎯 有出價上限 · ✅ 有空間的競標 · 🙈 隱藏競標中 | **可疊加** | 收窄注意力 |
| 隱藏 P(值得買) < N% | 門檻 | 濾掉沒把握的 |
| 排序下拉 | — | 分數（預設）／到手價／P 值／更新時間 |

### 「平台校正：開／關」（賣家版面上的切換）

**預設開著，正常情況不要關。**

Yahoo 是**競價出清價**、Mercari／PayPay 是**定價零售價**，同規格的成交價
差 2 倍以上（實測 Yahoo ×1.00／Mercari ×2.06-2.14／PayPay ×2.57-2.60）。
「校正：開」= 公允價校正到**標的自己的平台**；「關」= 混合平台的價格水準。

關掉會讓不同平台的價格被放在同一把尺上比 —— 這正是 `CLAUDE.md` 第三節
那六次事故的形狀。它存在只是為了讓你**看得出校正差多少**，看完切回去。

切換**不重抓**：後端一次把兩份估價都算好，前端切的是「看哪一份」。

- 疊加開關的設定**記在瀏覽器 localStorage**，關掉重開還在。全部清掉按「重設」。
- 同時選「🔨 競標」又開「🙈 隱藏競標中」→ 畫面會空。**那不是壞掉**，
  畫面會說明是設定互斥（空清單的三種原因文案是分開的：設定互斥／被篩掉／真的沒貨）。
- 分頁是**後端查詢**（撈整個資料庫），開關是**前端過濾**（只動眼前這批）。
  所以分類分頁看得到所有狀態的高價卡，開關只收窄你當下看到的清單。

## 四、旗標怎麼讀

| 類別 | 旗標 |
|---|---|
| **機會** | 🔥 白撿　📉 折價　🎯 可丟 offer　✅ 低於出價上限　🇺🇸 可寄美國地址 |
| **成本警告** | 🚚 運費吃掉（比行情）　🚚 運費佔比超標　❓ 需問寄送　💬 可問合併 |
| **證據不足** | ⚠️ 樣本少　🚨 可疑　🚫 樣本不足·無上限 |

**最後一組是工具在說「我沒把握」。** 特別是 🚫：它代表證據不夠格，
所以**拒絕給出價上限的數字**——不是算不出來，是不該算
（判準見 `CLAUDE.md` 第八節的四道閘門）。這時候靠你自己的判斷，不是靠工具的數字。

`P(值得買)` = P(公允價 > 到手成本)，相對於**估價模型的殘差分布**，
不是市場真實機率。**算不出 P 的標的不會被那道篩選隱藏**——沒有依據不等於不好
（`CLAUDE.md` 第一節：誤殺是靜默的）。

## 五、還沒做、但地基已經在的

**稀有卡降價盯哨**：分類跨狀態存活，代表「等降價」是一條持續有效的指令。
`listing_obs` 有價格歷史，可以在標為稀有卡的標的跌破某個幅度時推 Telegram。

尚未實作的原因是**門檻要看實際標出來的價格分佈才定得準**——
憑空定一個數字只會產生不想收的通知。等累積一批稀有卡之後再定。
